# Experiments

Use a stable run ID such as YYYYMMDD_dataset_model_task_nnn. The owner may be included as an attribution field, but the run ID should describe the experiment rather than a permanent personal branch.

Before recording a result, capture the dataset revision, split, task, model/checkpoint, config path, seed, server, output path, status, metrics, and notes. Do not fill rows with hypothetical results.


The public run registry uses `UNKNOWN` when the experiment-time Git commit was not recoverable. New tables distinguish development, validation, and same-source final analyses. Keep different cohorts, horizons, profiles, and conditions in separate rows; never infer physical action units without a verified schema. Current Core A/Core B V2 exposure and result links are in the server-sync release index.
